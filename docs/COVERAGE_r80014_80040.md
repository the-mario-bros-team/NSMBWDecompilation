# Coverage: `r80014_80040` (entry addresses `0x80014000..0x80040000`)

## How to read this file

This document describes one extraction lane of the NSMBW reconstruction. A
lane is a disjoint address range of `sys/main.dol`; this one owns every
function whose **entry address** is in `0x80014000..0x80040000` (image base
`0x80004000`). It is evidence-organized by address, not by game system.

- **Row -> code**: each row's `address` is the Ghidra entry address. All 20
  rows are **promoted**: the Rust function of the same number lives in
  `src/ui/hud.rs`, with its shared NW4R `lyt` primitives in `src/ui/lyt.rs`.
  No translated function remains in `src/subsystems/r80014_80040.rs`.
- **Evidence**: every `evidence` path is a file under
  `work/ghidra/main-gb/export/`, generated by Ghidra 12.1.4 from
  `work/dol/main.elf`. Those files are read-only reference.
- **Status**: `translated` = full control flow, all calls accounted for;
  `partial` = entry/exit and major effects present, with a marked gap;
  `stub` = address/role only.
- **Confidence**: `high` = strings/tables/offsets verified in the image;
  `medium` = control flow exact but one or more callee roles or vtable
  identities inferred; `low` = mostly unresolved.
- **Observed / inferred / unknown** markers inside the Rust file say where a
  claim comes from: `// observed:` (Ghidra output or image bytes),
  `// inferred:` (naming/role from call sites or strings), `// unknown:`
  (unresolved).

Terms: DOL, BRLYT/RLAN, NW4R, GX, r13/r2 are defined in `docs/GLOSSARY.md`.
Reading conventions for a single function are in `docs/READING_GUIDE.md`.

## Clusters

### A. `pointGet` scene (`0x80014F10..0x800151D0`, layout at `+0x04`)

A coin/counter pop-up scene. It loads `pointGet_02.brlyt` from its archive,
resolves six counter panes (`T_100_00`, `T_1000_00`, `T_red2_00`, `T_1UP_00`,
`T_coin_x_00`, `T_coinPoint_00`) plus `N_coin_00`, and animates one of them.
Scene state lives at `+0x1F8`; `4` means built/ready.

### B. `batteryInfo` warning scene (`0x80015D60..0x80016870`, layout at `+0x08`)

The "battery low" warning used by the Wii remote (and the four player slots).
It loads `batteryInfo/batteryInfo.arc` + `batteryInfo_10.brlyt`, binds four
`.brlan` animations, 9 node panes (`N_batt_00`..`N_batt`,
`Null_battPos1P`..`4P`), 20 battery pieces (`P_bat_00`..`P_bat_03`), and 8
text panes. The neighbouring state-table builder at `0x80016A80` names its
states `dWarningBattery_c::StateID_*`, which is where the class name is
inferred from.

### C. `errorInfo` warning scene (`0x80016F70..0x800175C0`, layout at `+0x08`)

The error/notification window. It loads `errorInfo/errorInfo.arc` +
`errorInfo_14.brlyt`, binds 10 window/button animations, 20 panes
(`A00_Window`, `B00_yesButton`, `B01_noButton`, `B02_centerButton`,
`C00_playerButton`), 9 text panes, and 3 button bases. The state-table
builder at `0x80018330` names its states `dWarningErrorInfo_c::StateID_*`.

## Uncertainties

- **Vtable identities** in `0x802FF7xx..0x80300xxx` are data addresses only.
  The roles of virtual methods `+0x10`, `+0x14`, `+0x18` are inferred from
  call order (load / close / notify); they are not named.
- **`0x802DCBFC`** is an unresolved indirect-jump stub (Ghidra could not
  recover the jump table). `fn_80015160` is therefore `partial`.
- **Pane visibility bit** `+0xBB` bit 0 is inferred: every "show" path sets it
  with `| 1` and every "hide" path clears it with `& 0xFE`. The surrounding
  NW4R pane fields are not otherwise reconstructed.
- **Controller type 3** in `0x800B4710` (`countLeadingZeros(entry-3) >> 5`) is
  only known to mean "entry == 3"; which device that is (Wiimote vs.
  extension) is not proven from this lane.
- **Global list `0x80377AB0`** (insert helper `0x80163850`) is a sorted list
  keyed by the byte at `node + 0x0C`; its owner (draw/update order) is
  inferred.
- **`0x800C8D60` / `0x800C8E40` / `0x800C8EB0`** are three variants of
  "resolve names to objects" that call different NW4R finders
  (`0x80007300`, `0x800073D0`, `0x80007320`). The exact finder kind (pane vs.
  material vs. texture) is not proven; the doc comments say "object".
- **Field roles** `+0x88`, `+0x208`, `+0x220`, `+0x224`, `+0x228`, and the
  page id `0x97` are recorded but not interpreted.
- **`0x80015D60` constructor callbacks** `0x80015E30` (8-byte ctor) and
  `0x8000FBF0` (dtor) are below the 16-byte rule and were not translated;
  only the four 12-byte records at `+0x254` are reconstructed.

## How these numbers were produced

`work/ghidra/main-gb/export/functions.tsv` was filtered on the hexadecimal
`address` column (`0x80014000 <= address < 0x80040000`), then on `size >= 16`.
No Ghidra run, no re-analysis, no source edits outside the lane: the C files
under `work/ghidra/main-gb/export/` are the only evidence used, plus raw
`work/dol/main.elf` bytes for the small-data bases and table contents.

The promotion pass that moved these 20 functions to `src/ui/hud.rs` and their
shared primitives to `src/ui/lyt.rs` used the same evidence only: no address,
body, or `# Original` block changed, and no new Ghidra run was made.
