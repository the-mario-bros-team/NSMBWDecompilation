# Translation pipeline

This is how a new function goes from binary evidence to a reader-facing Rust
module without breaking the tree.

## 1. Evidence

- Ghidra C: `work/ghidra/main-gb/export` (main.dol) or
  `work/ghidra/rel-<module>/export` (RELs).
- Function index: `functions.tsv` in the same directory.
- Raw instructions: `work/dol/main.elf` and `work/rels/elf/*.elf`.
- Assets: `work/arcs/index.json`, `work/arcs/extracted/`.

## 2. Translation

- Write directly into the semantic module; do not create a new range staging
  file (`src/subsystems/` only shrinks).
- Follow `docs/RUST_STYLE.md`: module header, plain-English function doc,
  `# Original`, `# Confidence`, `# Safety`.
- REL addresses are synthetic analysis addresses; say so in every doc block.
- Never invent Nintendo symbols; use `fn_<address>` and `// inferred:`.

## 3. Ledger

Add rows to `ledger/agents/<lane>.csv`:

```
module,address,name,status,confidence,evidence,rust_file
```

`module` is normalized from `rust_file` during merge, so the path is what
matters.

## 4. Gates

```powershell
.\scripts\check.ps1
```

which runs:

```powershell
cargo check
node tools/doc-lint.mjs src
node tools/merge-ledger.mjs
node tools/verify-ledger.mjs --enforce-bodies
node tools/index-functions.mjs
node tools/coverage-doc.mjs
node tools/progress.mjs
node tools/gap-report.mjs .
```

A lane is not merged while `cargo check`, `doc-lint`, or `verify-ledger`
fails. `verify-ledger` rejects duplicate addresses, missing Rust files, and
ledger rows absent from every Ghidra export. Since wave 241 it also runs with
`--enforce-bodies`, so a row whose module only *mentions* the address (call
site or plain comment, no `fn_<addr>` body, canonical `# Original` citation, or
attached `///` note about it) fails the gate. `gap-report` regenerates
`docs/GAP_REPORT.md`, the ranked list used to scope the next wave.

## 5. Generated artifacts

| File | Generated by |
|---|---|
| `ledger/functions.csv` | `merge-ledger.mjs` |
| `ledger/SUMMARY.md` | `merge-ledger.mjs` |
| `docs/FUNCTION_INDEX.md` | `index-functions.mjs` |
| `docs/COVERAGE.md` | `coverage-doc.mjs` |
| `docs/PROGRESS.md` | `progress.mjs` |

Never hand-edit these; fix the source ledger or the generator.

## 6. Promotion

Staging is a temporary state. `docs/PROMOTION.md` maps clusters to semantic
modules. Promotion moves definitions; it does not copy them. The goal is for
`src/subsystems/` to contain only tombstones and next-target notes.
