# Coverage — `0x80040000..0x80080000` (actor / player range)

## How to read this file

This document tracks one translation lane: main.dol functions whose **entry
address** is in `0x80040000..0x80080000`. It is a navigation aid, not a second
translation.

* **Address** — virtual entry point in the DOL image (not a file offset).
* **Name** — the Ghidra name. No original symbol table survives, so
  `FUN_<address>` is the honest identity; descriptive roles are marked as
  inferred in the Rust doc comments.
* **Role** — one plain sentence. Roles marked *(inferred)* come from call
  sites, strings or field use, not from a recovered symbol.
* **Status** — `translated` = full control flow, all calls accounted for but
  still staged in the range module; `promoted` = translated and **moved** to a
  semantic module (see Module); `partial` = behavior is known but one
  machine-level detail (here: `r12`) is not expressible; `stub` = address/role
  only.
* **Confidence** — strength of **evidence**, not code quality:
  `high` = instruction-level match, `medium` = some field roles guessed,
  `low` = unresolved.
* **Module** — where the Rust body lives (paths are relative to `src/`). A
  promoted function exists **only** in its semantic module; promotion moves
  code, it never copies it.
* **Evidence** — the Ghidra C file under `work/ghidra/main-gb/export/`. The
  Rust body is under the same `fn_<address>` name in the file named by Module.

Status and confidence are copied to `ledger/agents/r80040_80080.csv`; the
`module` and `rust_file` columns of a promoted row point at its new home.

**Range totals.** `functions.tsv` lists **1,015** entries in this range;
**874** are at least 16 bytes. The other **141** are shorter than 16 bytes and
were excluded by the task's minimum-size rule. This pass translates **20**
entries (2.3 % of the ≥16-byte population), chosen for clear evidence rather
than for address contiguity.

## Clusters

### A. Destructor and vtable plumbing (`0x80040540..0x800408F0`)

**Promoted → `src/runtime/cpp.rs`.** Five entries cover a complete, reusable
shape:

1. `0x80040540` / `0x800405A0` — conditional release helpers in the
   deleting-destructor shape. They call the shared thunk at `0x8015F800(this,
   0)` (a no-op for a zero flag) and then free through `0x802B9280` when the
   signed second argument is positive.
2. `0x80040720` — a five-times-unrolled chain walk over `+0x30` links, with a
   tail recursion on the fifth node.
3. `0x80040800` — name-tail comparison built on `strrchr` (`0x802E1C40`) and
   `strcmp` (`0x802E1AB4`).
4. `0x800408C0` — a thunk that adjusts `this` to a secondary base at `+0x18`
   and dispatches through `0x802DCBFC` using `r12`.

**Same shape elsewhere in the range:** `0x80043430/90`, `0x80044E50/EB0` and
`0x80046070/80046410` contain further copies of the destructor/walk/compare
family. They are not translated yet; their bodies are near-identical, so a
later pass can batch them after confirming each vtable type — and should add
them to `runtime/cpp.rs`, not here.

### B. `obj_dokan` pipe actor (`0x80041C00..0x80042A70`)

**Promoted → `src/game/actors/dokan.rs`.** This is the most coherent cluster in
the range. Strings `obj_dokan_A/B/CU/CD/D`, `g3d/obj_dokan.brres` and the field
layout tie the five functions together:

* `0x80041C00` decodes the spawn parameter word at `+0x04`
  (`variant = (p >> 4) & 3`, `player = (p >> 12) & 3`, `kind = (p >> 16) & 0xFF`),
  writes the transform/bounds block, calls the class spawn slot `+0xD4`, and
  starts sound `0x70E` at the projected position.
* `0x80041D40` loads the BRRES, resolves the main model (`obj_dokan_D` for
  `kind < 2 && variant != 1`, otherwise the table at `0x80306CFC`), creates 32
  `B` parts at `+0x3C0` (stride `0xC`) and one `CD` model at `+0x540`.
* `0x80042350` advances three angles by the signed delta at `+0x550`.
* `0x80042970` runs the destructor slot `+0xE8` and unlinks `+0x3FC`.
* `0x80042A70` is a create hook that forwards its argument to `0x80162510`
  and returns `0`.

The related, still-untranslated `0x80045710` (732 bytes) loads the same
BRRES with `A`/`B` models and four animation bindings; it is the best next
read in this cluster, and its natural home is `game/actors/dokan.rs`.

### C. Player state and physics (`0x8004B160..0x8004BF80`)

**Promoted → `src/game/player.rs`.** Six functions describe the gameplay
player's current pose without touching the renderer:

* predicates: `0x8004B160` (near-stop), `0x8004B1A0` (flag `0x80`),
  `0x8004B1C0` (flag plus animation id), `0x8004BF00` (three-way pose);
* table/data access: `0x8004B520` (animation rate from `0x802EE9B4`) and
  `0x8004BF80` (copy 9 floats from one of three blocks).

`0x8004B520` is the template for the unselected siblings `0x8004B4C0`,
`0x8004B580` and `0x8004B5E0`: same address arithmetic, different tables
(`0x802EE978`, `0x802EE9F0`, `0x802EEA2C`). `0x8004B4C0` and `0x8004B580`
forward a second direction argument; `0x8004B5E0` calls `0x800707E0` instead,
for which Ghidra shows a single argument.

### D. Player animation and effects (`0x80048C40..0x8004CD20`)

**Promoted → `src/game/player.rs`.** `0x80048C40` and
`0x8004CD20` are thin wrappers over `0x8008FB60`, which binds a player index
into an SDA global, calls `0x8016C890`, and restores the global to `-1`. The
effect names (`Wm_mr_misshit`, `Wm_mr_spsmoke`) are observed strings; the
gameplay trigger for each is inferred.

### E. Byte helpers (`0x800483F0`, `0x8004DE30`)

**Promoted → `src/runtime/cpp.rs` (appended).** They are vocabulary, not a
subsystem: two leaf functions with no calls. `0x800483F0` decrements a
saturating-at-zero byte counter; `0x8004DE30` turns a byte into a boolean. Both
are useful for reading larger player functions later, and they carry no
player-specific knowledge, so they sit with the object-field helpers.

## Where Ghidra C and the PowerPC bytes disagree

These were checked against `work/dol/main.elf` and are documented on the
functions. The Rust follows the bytes. All four rows now live in semantic
modules: `0x800405A0` and `0x800408C0` were already in `runtime/cpp.rs`, this
pass added `0x800483F0` to `runtime/cpp.rs` and moved `0x8004B520` to
`game/player.rs`.

| Address | Ghidra C | Instruction stream |
|---|---|---|
| `0x800405A0` | one null test | two null tests (`beq` at `0x800405C4`) |
| `0x800408C0` | two arguments, no `r12` | two arguments, but sets `r12 = a1 + 0x18` before the tail call |
| `0x800483F0` | signed `char` | `lbz`; unsigned byte |
| `0x8004B520` | one argument, `double` return | second argument is forwarded in `r4`; float returned in `f1` |

`0x80041C00` also deserves a note, but it is **not** a behavioral mismatch:
the instructions form `angle + 0x8000` while Ghidra prints `angle - 0x8000`.
For a 16-bit angle store the two are identical, so either spelling works.
