- `0x801AB150`: `set_gqr` is a host stub for the eight `mtspr 912+i` writes that
  are inlined inside `init_hardware_paired_single`; it has its own callers.
- `0x801AD4E0`: three deliberate thin forwarders with different arities
  (`dvd_report3`/`dvd_report4`/`sdk_panic`), kept as arity adapters.
- `0x80296750`: `fn_802d88c0` is a 2-instruction `.ctors` thunk that
  tail-calls `0x80296750`; its `# Original (untabled)` block cites the callee's
  address, which is what the scan groups on. The bodies differ.
- `0x802D0CC0`: same pattern - `fn_802d1d90` tail-calls the constructor
  `0x802D0CC0`; the address is the callee's, not a second body.

These are the same four families recorded in `work/wave234/laneA_report.md`.

Wave 256 resolved the two citation groups and re-verified the adapters with the
new semantic pass of `tools/check-dupe-bodies.mjs`:

- `0x80296750` / `0x802D0CC0`: the two `.ctors` thunks now cite their own slot
  addresses (`0x802D88C0` / `0x802D1D90`) as untabled entries and mention the
  callee as an ordinary reference, so no address is claimed twice.
- `0x801AB150`: `set_gqr` keeps the "inlined into `FUN_801ab150`" provenance,
  which the gate does not read as a body claim, and its body now carries an
  explicit `// adapter:` marker.
- `0x801AD4E0`: all three forwarders carry `// adapter:` markers; a group made
  only of adapters is admissible, so the address stays a single `stub` ledger
  row with no competing body.

The semantic pass also caught one real duplicate: `0x800967A0` was translated
twice (`game::enemies::c243_shared_tail` and `game::stage::fn_800967a0`). The
stage body was corrected to the raw register image (`mr r3,r4` makes the second
argument the virtual receiver) and the enemies helper now delegates to it.

## 4. Arity scan

`work/wave239/laneA_arity.mjs` sweeps every `callN(addr, ...)`,
`call0_ret(addr)` and `abi_callN!(addr, ...)` site whose first argument
resolves to an absolute address and compares the supplied argument count with
the callee's translated `fn_<address>` signature.

```text
# address-call arity sweep
# 68 files, 19266 translated addresses, 42651 resolved address-call sites
# mismatches: 2410 = 1141 under-supplied + 1269 over-supplied
# under-supplied whose callee reads a missing argument: 0
# under-supplied whose extra parameters are unused: 1141
# (variadic callees excluded: 1178 sites, 15 addresses; ambiguous defs: 0)
```

**No live arity defect**: 0 of the 1,141 under-supplied sites read a parameter
they do not pass. The 1,141 are ABI-slot padding where the callee body never
reads the missing argument; the 1,269 over-supplied sites pass arguments the
translated body ignores. Both classes are the documented `platform::callN`
convention, not errors.
